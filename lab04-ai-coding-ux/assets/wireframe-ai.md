Label ชัดเจนและอยู่ด้านนอก (Accessibility): การใช้ Label * อีเมล และ * รหัสผ่าน วางไว้ด้านบนช่องกรอกอย่างชัดเจน ช่วยให้ผู้ใช้ที่ทักษะเทคโนโลยีระดับ 1 ไม่สับสน เพราะหากใช้แค่ Placeholder (ตัวหนังสือสีจางในช่อง) เมื่อพิมพ์ข้อความลงไปแล้วคำอธิบายจะหายไป ทำให้ผู้ใช้สูงอายุลืมว่าช่องนี้ต้องกรอกอะไร

สัญลักษณ์บังคับกรอก (Usability): การใส่เครื่องหมาย * หน้าฟิลด์ เป็นจุดสังเกตสากลที่ช่วยบอกผู้ใช้ทันทีว่าช่องนี้ห้ามเว้นว่าง

ขนาดและตำแหน่งของปุ่ม (Usability): ปุ่มหลัก [ เข้าสู่ระบบ ] ถูกออกแบบให้มีขนาดใหญ่ (Full-width) และวางแยกออกมาด้านล่างช่องกรอกอย่างชัดเจน เพื่อเพิ่มพื้นที่ในการสัมผัส (Touch target) แก้ปัญหาผู้ใช้นิ้วใหญ่กดพลาดบ่อย ส่วนปุ่มรอง [ ลืมรหัสผ่าน ] ถูกจัดวางไว้ด้านล่างปุ่มหลักและมีจุดเด่นน้อยกว่า เพื่อป้องกันการเผลอกดผิด

ข้อความ Error Message อธิบายวิธีแก้ (Accessibility): แทนที่จะบอกแค่ว่า "อีเมลผิด" หรือ "รหัสผิด" ระบบจะใช้ไอคอน ⚠️ ควบคู่กับสีเตือน (Warning) และบอกวิธีแก้ไขที่ชัดเจน เช่น "กรุณาตรวจสอบให้แน่ใจว่ามีเครื่องหมาย @" ซึ่งช่วยลดความหงุดหงิดของผู้ใช้ที่แก้ปัญหาไม่ถูก

ข้อความสำเร็จ (Success State): แม้จะเป็นหน้า Login แต่การมีข้อความตอบรับ [✔️] เข้าสู่ระบบสำเร็จ! แสดงขึ้นมาก่อนที่ระบบจะโหลดเปลี่ยนหน้า จะช่วยให้ผู้ใช้รับรู้ว่าการกดปุ่มของตนเองนั้นได้ผลแล้ว ป้องกันปัญหาผู้ใช้ใจร้อนกดย้ำๆ หลายครั้งจนระบบรวน

คำอธิบายการออกแบบที่ช่วยเรื่อง Usability และ Accessibility

ข้อความสำเร็จและแจ้งเตือน (Success & Warning States): มีการใช้แถบ [✔️] สำเร็จ: ... ที่ด้านบนสุดเพื่อให้เห็นทันทีหลังทำรายการเสร็จ ช่วยลดความกังวลของผู้ใช้ (Usability) และในส่วนสินค้าใกล้หมดมีการใช้ไอคอน ⚠️ และ [❗️] ควบคู่กับคำอธิบาย "ต่ำกว่าเกณฑ์" ทำให้ผู้ใช้รับรู้ถึงระดับความสำคัญได้โดยไม่ต้องพึ่งพาสีเพียงอย่างเดียว (Accessibility)

หัวข้อชัดเจน (Clear Headings): แบ่งสัดส่วนหน้าจอด้วยหัวข้อที่อ่านเข้าใจง่าย เช่น "แจ้งเตือนด่วน: สินค้าใกล้หมดสต็อก" และ "สรุปสต็อกสินค้าคงเหลือทั้งหมด" ทำให้ลุงสมหมายที่สายตายาวกวาดสายตาหาข้อมูลที่ต้องการได้ทันทีโดยไม่ต้องเดา (Accessibility)

ชื่อปุ่มบอกหน้าที่ชัดเจน (Descriptive Buttons): แทนที่จะใช้คำสั้นๆ กำกวมอย่าง "เพิ่ม" หรือ "ดู" ระบบใช้คำว่า [ + ไปหน้าเพิ่มสินค้าเข้าคลัง ] และ [ ดูรายการสินค้าคงเหลือทั้งหมด ] ซึ่งสื่อความหมายชัดเจนว่ากดแล้วจะเกิดอะไรขึ้น (Accessibility)

ขนาดและตำแหน่งของปุ่มหลัก (Usability): ปุ่ม [ + ไปหน้าเพิ่มสินค้าเข้าคลัง ] เป็นปุ่ม Action หลักที่ถูกออกแบบให้มีความกว้างเต็มหน้าจอ (Full-width) และจัดวางไว้ในตำแหน่งบนสุดของพื้นที่เนื้อหา ช่วยเพิ่มพื้นที่สัมผัส แก้ปัญหาเรื่องนิ้วใหญ่กดพลาด และทำให้ผู้ใช้เข้าถึงฟังก์ชันสำคัญได้รวดเร็วที่สุด

การจัดเรียงความสำคัญ (Information Hierarchy): นำส่วน "แจ้งเตือนสินค้าใกล้หมด" ขึ้นมาก่อน "สรุปสต็อกภาพรวม" เพราะเป็นข้อมูลที่ต้องการความสนใจ (Actionable data) ทันที ซึ่งตอบโจทย์ Goals และ Pain points ของผู้ใช้ที่ต้องการเห็นสถานะของขาดได้ทันทีโดยไม่ต้องเพ่งหาครับ

คำอธิบายการออกแบบที่ช่วยเรื่อง Usability และ Accessibility

ลำดับการอ่านและการกด Tab (Accessibility): โครงสร้างหน้าจอถูกออกแบบให้เรียงจากบนลงล่าง (Top-to-Bottom) อย่างเป็นระเบียบ เมื่อลุงสมหมายเลื่อนหน้าจอ หรือใช้ปุ่ม Tab ลำดับโฟกัสจะไล่จาก ชื่อสินค้า -> รหัสสินค้า -> หมวดหมู่ -> จำนวน -> ราคา -> ปุ่มบันทึก ซึ่งเป็นลำดับธรรมชาติที่เข้าใจง่ายที่สุด

Label ที่มองเห็นชัดเจนและสัญลักษณ์ * (Accessibility & Usability): ใช้ Label วางไว้ด้านบนของทุกช่องกรอก (เช่น * ชื่อสินค้า (Product Name) :) เพื่อให้คนสายตายาวอ่านได้ง่าย และไม่หายไปเมื่อเริ่มพิมพ์ข้อความ (ต่างจาก Placeholder) พร้อมใส่สัญลักษณ์ * ในฟิลด์ที่บังคับกรอก เพื่อลดความสับสนว่าช่องไหนต้องกรอกบ้าง

ปุ่มเพิ่ม/ลดจำนวนขนาดใหญ่ (Usability): ในช่อง * จำนวน (Quantity) มีการออกแบบปุ่ม [ - ] และ [ + ] ขนาดใหญ่ขนาบข้างช่องตัวเลข เพื่อแก้ Pain point เรื่องนิ้วใหญ่พิมพ์ไม่ถนัด ลุงสมหมายสามารถกดบวกตัวเลขได้เลยโดยไม่ต้องพยายามจิ้มคีย์บอร์ดบนหน้าจอ

Error Message ที่บอกวิธีแก้ปัญหา (Accessibility): ข้อความแจ้งเตือนสีแดง (ในดีไซน์จริง) จะอยู่ใต้ช่องที่กรอกผิดทันที และไม่ได้บอกแค่ว่า "ผิดพลาด" แต่จะอธิบายวิธีแก้ เช่น "จำนวนสินค้าต้องมากกว่า 0 กรุณากดปุ่ม + เพื่อเพิ่มจำนวน" ช่วยให้ผู้ใช้ที่ทักษะเทคโนโลยีน้อยสามารถแก้ไขด้วยตัวเองได้

ตำแหน่งของปุ่มหลักและปุ่มรอง (Usability):

ปุ่มหลัก [ บันทึกข้อมูล ] วางไว้ล่างสุดของฟอร์ม เป็นปุ่มขนาดใหญ่เต็มความกว้าง (Full-width) เพื่อให้สัมผัสง่าย และเป็นจุดสิ้นสุดสายตาหลังจากกรอกข้อมูลเสร็จ

ปุ่มรอง [ ยกเลิก ] วางไว้ใต้ปุ่มหลักและทำให้มีความเด่นน้อยกว่า (เช่น เป็นแค่เส้นขอบหรือตัวหนังสือเฉยๆ) เพื่อป้องกันการเผลอกดผิดจนข้อมูลที่พิมพ์มาทั้งหมดหายไป

ข้อความสำเร็จ (Success State): แถบแจ้งเตือน [✔️] สำเร็จ ถูกจัดวางไว้บนสุดของฟอร์ม (เหนือพื้นที่กรอกข้อมูล) เพื่อให้ผู้ใช้สังเกตเห็นทันทีเมื่อหน้าจอรีเฟรชหรือบันทึกข้อมูลเสร็จ ป้องกันพฤติกรรมการกดย้ำๆ เพราะไม่แน่ใจว่าระบบบันทึกไปหรือยัง
