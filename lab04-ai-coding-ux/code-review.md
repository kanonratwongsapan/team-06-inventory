## รีวิวเมธอด `reduce_stock`
- **ชี้จุด:** บรรทัดที่ 14-15 (`if self.stock.get(product_id, 0) - amount < 0:`)
- **ทำไมผิด:** docstring บอกว่าถ้าน้อยกว่า "หรือเท่ากับ" 0 ต้องเตือน แต่โค้ดใช้เครื่องหมาย `<` (น้อยกว่า) อย่างเดียว
- **กรณีที่ทำให้พัง:** ถ้ายอดสต็อกเหลือ 0 พอดี โค้ดจะไม่แจ้งเตือน แต่จะยอมให้ทำรายการต่อจนสต็อกกลายเป็น 0
- **เสนอทางแก้:** เปลี่ยนเงื่อนไขเป็น `<= 0`

- **ชี้จุด:** บรรทัดที่ 11 (`self.total_value -= amount * 100`)
- **ทำไมผิด:** โค้ดทำการหักมูลค่า `total_value` ก่อนที่จะตรวจสอบว่าสต็อกพอให้หักหรือไม่ ถ้า Error บรรทัดถัดไป มูลค่าจะถูกหักไปฟรีๆ ทำให้ state ข้อมูลพัง
- **กรณีที่ทำให้พัง:** สั่งลดสต็อก 5 ชิ้น แต่สต็อกจริงมี 2 ชิ้น (ฟังก์ชันจะ raise ValueError แต่ `total_value` ถูกหักไปแล้ว)
- **เสนอทางแก้:** ย้ายบรรทัดหัก `total_value` ไปไว้ล่างสุดหลังจากการอัปเดตสต็อกสำเร็จแล้ว

- **ชี้จุด:** บรรทัดที่ 18-19 (`current_stock = self.stock[product_id]`)
- **ทำไมผิด:** เป็นการอ่านค่ามาเก็บไว้ในตัวแปรก่อน แล้วค่อยเขียนทับ หากมี 2 thread เข้ามาทำงานพร้อมกัน จะเกิด Race condition
- **กรณีที่ทำให้พัง:** Thread A และ B สั่งลดสต็อก 1 ชิ้นพร้อมกัน ตอนที่สต็อกมี 5 ชิ้น ทั้งคู่จะอ่านค่า 5 ไปพร้อมกัน และเขียนทับด้วย 4 ทั้งคู่ แทนที่สต็อกจะเหลือ 3
- **เสนอทางแก้:** ใช้ Database Transaction หรือ Lock mechanisms ในการจัดการ หรือลดรูปเป็น `self.stock[product_id] -= amount` โดยตรงถ้าทำแบบ atomic

## รีวิวเมธอด `get_average_price`
- **ชี้จุด:** บรรทัดที่ 25 (`return total_price / total_items`)
- **ทำไมผิด:** ไม่มีการดักจับกรณีที่ตัวหารเป็นศูนย์
- **กรณีที่ทำให้พัง:** หากไม่มีข้อมูลสินค้าในระบบเลย หรือส่งค่า `total_items = 0` เข้ามา โปรแกรมจะพังทันที (ZeroDivisionError)
- **เสนอทางแก้:** เพิ่มเงื่อนไข `if total_items == 0: return 0.0` ก่อนทำการหาร
